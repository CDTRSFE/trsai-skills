# build-and-package（构建并交付压缩包）

用于 `provider: "local"` 的部署、构建、直接打包请求。读取 [../providers/local.md](../providers/local.md)。

## 配置及部署 Tag

1. 先选环境：默认 `dev`；明确生产打包才选 `prod`。读取 `deploy.json`，缺失时按本地 provider 发现并保存所选环境配置。
2. 校验构建命令、包管理器和依赖是否可用。将两个目录解析为绝对路径，确认产物目录不是项目根目录或项目外目录，归档目录在项目内且不位于产物目录中；拒绝经符号链接绕过这些边界的路径。
3. 复用部署入口的运行时 Tag 输出检查：若没有在控制台或项目既有诊断位置输出真实构建 Tag 的能力，说明原因并按现有确认规则补充最小代码，将相关修改提交并推送分支。不要只在构建终端打印 Tag 来替代运行时代码输出。
4. 使用 `git-tag-release` 的内置脚本预览，传入所选 `target`、`editPkg=true` 和 `pushBranch=true`。展示最终 Tag、前缀来源、回写/提交及推送动作，沿用该技能的确认和执行流程；使用预览得到的原样 Tag 执行，不另写版本算法。
5. 确认 `package.json#tag`、本地 Tag 指向的 Commit、待构建 HEAD 一致，并核实分支和 Tag 推送成功。构建相关的未提交修改必须先解决，不能把与 Tag 不一致的源码交付为该版本。Tag 或推送失败则停止并报告，不继续声称打包部署成功。

## 构建与压缩

1. 遵守显式的 `confirmBeforeStart`。对已存在的产物目录，优先用构建工具已确认的清理机制；否则将旧目录移至唯一备份位置，避免删除用户文件。不得直接打包旧目录。
2. 在项目根目录执行所选 `buildCommand`，等待本次命令结束。非零退出立即停止；即使有旧 ZIP 或旧产物也不交付为本次成功。若 Tag 已推送，单独报告这一事实，不删除或重建该 Tag。
3. 仅在本次构建成功且产物目录存在、含实际文件时继续。确认输出中含本次真实 Tag，或通过项目已有运行验证机制核实；若无法验证，说明缺口并停止成功交付。
4. 创建 `archiveDir`，以 `<项目名>-<最终Tag>-<时间戳>.zip` 命名。文件名片段中的路径分隔符等不安全字符替换为 `-`，不改变实际 Git Tag。避免覆盖同名包，冲突时追加唯一后缀。
5. 使用可用的 ZIP 工具（如 Python `zipfile`）直接压缩实际产物目录，保留该目录原名作为 ZIP 内的顶层目录，并保留内部文件名、相对目录结构及必要的隐藏产物。例如产物为 `dist/` 就归档为 `dist/`，产物为 `build/` 就归档为 `build/`；不要统一改成 `dist/`，也不要用项目名、Tag 或 ZIP 文件名重命名包内目录或额外套目录。默认只按上一步命名 ZIP 文件；只有用户明确指定时才调整包内目录名或结构，不重命名磁盘上的构建目录。例如 Python `zipfile` 默认的 `arcname` 使用 `<outputDir末级目录原名>/<相对于outputDir的路径>`。只归档产物，不归档仓库源码、`.git`、`node_modules`、旧 ZIP 或本地凭据。对产物中的符号链接先检查，不跟随指向产物目录之外的链接。
6. 检查 ZIP 存在且非空，执行完整性校验（如 `ZipFile.testzip()`），核对条目与本次产物一致，且默认所有产物条目均位于以实际产物目录原名命名的顶层目录下，内部相对路径保持不变；用户明确指定其他归档结构时按其要求核对。失败则停止并报告，不能仅凭压缩命令返回成功交付。
7. 构建和压缩成功后，按 [discover-config.md](discover-config.md) 的 Git 后续规则提交并推送本次 `deploy.json` 改动。不把 ZIP、产物目录或无关文件提交进仓库。记录构建 Tag 对应的 Commit；配置后续提交不冒充构建 Commit。配置提交/推送失败单独报告，不否定已校验的 ZIP。

## 文件交付

最终报告只保留一个目录链接，文案固定为“ZIP 所在目录”，目标为已验证 ZIP 所在目录的真实绝对路径。不再输出“下载 ZIP”“打包文件”等压缩包直链，不输出虚构链接或相对路径：

```text
打包完成：<项目> / <环境>
Tag：<最终Tag>
Commit：<构建Commit>
压缩包：<文件大小>

[ZIP 所在目录](</实际绝对路径/目录>)
```

链接点击行为取决于客户端，不承诺目录链接一定打开文件管理器。支持本地桌面时，生成后定位实际文件：macOS 使用 `open -R <ZIP绝对路径>`，Windows 使用 Explorer 的选择文件功能，Linux 使用可用的文件管理器打开所在目录。通过参数数组或可靠的 shell 引号传路径；定位失败不影响 ZIP 交付，仍提供“ZIP 所在目录”链接；必要时补充目录的完整路径供用户查找发送。不自动发送给其他人。
