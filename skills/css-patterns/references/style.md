# 样式约定参考

脚手架项目已有 stylelint、Prettier 和提交校验。本文件记录 stylelint 无法完全表达的团队判断。

只要在写样式，无论是普通页面、小卡片、组件局部细节，还是复杂布局，都应先按这里的判断处理。不是只有大屏、响应式或大型布局场景才需要关注样式方案。

## UnoCSS 优先

优先用 UnoCSS 处理：

- 布局：flex、grid、positioning
- 间距：margin、padding、gap
- 尺寸：width、height
- 颜色：text、bg、border
- 排版：font-size、font-weight、line-height
- 响应式、hover/focus/disabled、过渡动画

## CSS / Less 适用场景

- `:deep()` 覆盖第三方组件内部结构。
- `::before` / `::after` 伪元素。
- `@keyframes` 动画。
- CSS 变量声明与复杂动态样式。
- UnoCSS 不便表达的 grid area 或复杂选择器。

## 文本溢出与收缩边界

写列表项、卡片、标题行、说明文案、标签组和图表旁信息时，必须先确定文本如何处理超长内容。

- flex / grid 子项承载文本时，文本所在项以及必要的父级必须允许收缩：优先补 `min-w-0`，纵向滚动区域补 `min-h-0`。
- 单行展示的标题、描述、时间、来源等字段必须使用明确的截断策略，例如 UnoCSS `truncate`，并确保父级有确定宽度或可收缩宽度。
- 多行展示的正文必须明确是换行还是限制行数：可换行时使用 `break-words` / `overflow-wrap:anywhere`，限制行数时使用 `line-clamp-*` 或项目已有等价样式。
- 同一行里左侧长文本 + 右侧时间、按钮、状态标签时，左侧容器用 `flex-1 min-w-0`，右侧信息用 `shrink-0`，避免长文本把右侧或外层撑出。
- 大屏、看板、弹窗和窄侧栏不允许依赖“真实数据不会太长”的假设；必须用长中文、连续英文、URL、数字串等极端文本做一次视觉检查。
- 不要只在外层写 `overflow-hidden` 掩盖问题；应同时设置子项收缩、文本截断或换行策略。

## 样式穿透

- 优先缩小父级作用域，再写 `:deep()`。
- 不要写全局污染式覆盖。
- 不要为了覆盖组件库滥用 `!important`。

## z-index

- 优先遵循组件库弹层层级。
- 局部层级只在当前组件作用域内处理。
- 避免魔法大数，例如 `999999`。
