# Forge Starter

## 首轮回复格式（先判断）

适用条件：用户要求创建工程，且本轮及前文均未明确工程类型。

按当前环境选择一种询问方式，同一问题只提出一次：

### 有可用的选择控件时（优先）

使用当前模式允许的交互提问工具，问题标题为 `请问你创建工程的类型`，选项按顺序为 `1. 大屏`、`2. PC`。例如环境提供 `request_user_input_async` 时，使用以下参数：

```json
{"questions":[{"title":"请问你创建工程的类型","options":["1. 大屏","2. PC"]}]}
```

提问后保持等待用户回答的状态。异步工具调用返回只表示控件已展示，不表示用户已经回答；预选项、空结果或等待时间结束都不是选择。此时不再用正文或最终回复重复提问，也不追加“请先选择工程类型：大屏或 PC”等催答文字，不改用文字方式再问一次。收到回答后再继续。

### 没有可用的选择控件时

最终回复的完整正文为以下三行，逐字输出，保留换行；代码围栏仅用于界定文案，实际回复不带代码围栏：

```text
请问你创建工程的类型
1. 大屏
2. PC
```

这三行是文字询问的固定格式，不是可改写的示例。输出前核对：第一行原文一致，第二行是 `1. 大屏`，第三行是 `2. PC`。不要合并成“你要创建大屏工程还是 PC 工程？”。两种询问方式都不追加技能链接、引用、入口差异说明或“技能要求先确认”等解释。这里收集的是缺失的工程类型，不是请求执行授权。

等待用户回复：`1` / `大屏` / `1. 大屏` → 大屏，`2` / `PC` / `2. PC`（不区分大小写）→ PC，然后进入下方信息收集流程。已经明确类型的请求跳过本节。

## 概览

创建 TRS Vue/Vite 前端工程：先明确工程类型，再展示工程信息、确定存放路径，随后生成工程、初始化 Git、自动安装依赖，最后汇总实际结果。

项目模板地址：https://github.com/CDTRSFE/vite-tpl.git

## 创建前收集信息

首先检查用户是否已明确工程类型。未明确时，严格执行上方“首轮回复格式”，等待选择后再进入本节。

按上方映射识别控件选择或文字回复，然后直接进入后续流程，不再要求用户重复确认类型。只有用户已回复但内容无法确定类型时，才通过原询问方式请用户重新选择，不猜测。

等待用户选择后再继续，不擅自默认 PC，不在类型未确定时进入后续工程信息收集、下载模板、创建目录或安装依赖。用户已明确类型时跳过此询问，不重复提问。

类型确定后，展示以下三项待创建信息，并沿用用户在前文提供的名称和路径：

| 信息 | 取值规则 |
| --- | --- |
| 工程类型 | `pc` / `大屏`；使用用户已明确的类型，未明确时让用户选择，不擅自默认 |
| 工程名 | 使用用户指定名称；未指定时默认 `my-project`，不从业务描述另起名称 |
| 存放路径 | 邀请用户指定父目录；未指定时采用当前工作目录，并展示拼接工程名后的绝对路径 |

用户选择“大屏”后，输出示例（替换为真实绝对路径）：

```text
待创建的工程信息：
- 工程类型：大屏
- 工程名：my-project（默认，可修改）
- 存放路径：<当前工作目录绝对路径>/my-project（默认，可指定其他位置）

请指定存放路径，或回复“默认”采用以上位置；工程名也可一并修改。
```

缺少存放路径时，给用户一次指定或采用默认位置的机会。用户回复后仍未指定路径，则采用已展示的默认位置；未指定名称则采用 `my-project`，不重复追问。用户已提供所需信息或明确要求其余使用默认值时，展示后直接执行，无需再次确认。

路径约定：用户提供父目录时在其下创建工程名目录；用户明确提供工程完整路径时直接使用，不重复追加工程名。创建前检查目标目录；目录已存在且非空时停止并询问如何处理，不覆盖已有内容。

## 创建及依赖安装

- 推荐 Node.js `20.9.0+`；检查模板的 `engines` 和 `packageManager`，遵循其版本要求。
- 默认使用 `pnpm`，除非用户明确要求其他包管理器。
- 根据工程类型执行下方的入口配置，并在结果中展示实际配置。当前模板的 PC 和大屏使用同一下载命令，大屏通过内置 `ScaleLayout` 组件启用，不是独立分支或命令参数。

使用 `vite-tpl` 文档指定的命令，将 `<project-dir>` 替换为确定的目标路径，包含空格时正确引用：

```shell
npx degit CDTRSFE/vite-tpl <project-dir>
cd <project-dir>
git init
pnpm install
```

依次执行并检查每步结果。**安装依赖是创建流程的默认必做步骤，不再要求用户自行执行 `pnpm i`。** 若用户明确要求跳过安装，则遵循该要求并在结果中注明。

如果 `pnpm` 不可用，检查 Corepack 等可用方式，按模板要求准备并执行安装。依赖安装失败时，检查错误并修复可处理的问题后重试；仍无法完成则如实报告工程已生成但依赖安装失败、具体原因及下一步，不宣称工程已就绪。

不默认启动常驻开发服务；完成后给出启动命令。

## 按工程类型配置入口

已核查远程 `master` 提交 `3987fcc`：模板包含 `src/components/ScaleLayout.vue`，但默认 `src/App.vue` 未使用该组件；README、package.json 和 Vite 配置没有独立的大屏创建命令。后续远程模板若有变化，应检查实际文档与源码再调整，不能猜测 `--screen` 参数或大屏分支。

| 工程类型 | 下载后执行 |
| --- | --- |
| `pc` | 保留模板默认入口，不挂载 `ScaleLayout` |
| `大屏` | 在 `src/App.vue` 引入并挂载现有 `ScaleLayout`，启用大屏画布缩放 |

大屏入口配置：

1. 在 `src/App.vue` 的 `<script setup>` 中显式引入 `import ScaleLayout from './components/ScaleLayout.vue';`。
2. 用 `<ScaleLayout :w="1920" :h="1080" fit="fill">` 包裹现有根模板内容。保留原有 `a-style-provider`、`a-config-provider`、路由、消息和弹窗上下文，不重写现有入口逻辑。
3. 用户指定画布尺寸或缩放方式时采用其配置；否则沿用组件默认值 `1920×1080`、`fill`。`fill` 按宽高分别缩放以铺满窗口；`contain` 等比缩放并居中留边。
4. 该组件缩放整个 `body`，在应用根部仅挂载一次；不要在每个页面重复挂载，也不要另造缩放组件。此步骤只启用大屏布局，不代表已生成业务看板。
5. 安装依赖并配置入口后，执行模板提供的 `pnpm build` 验证可编译；失败时报告具体原因，不宣称大屏工程已就绪。

## 完成验证和结果输出

确认目标路径下存在 `package.json`、源码和模板配置，检查 Git 初始化结果，以及依赖安装命令是否成功退出。只有实际安装成功才写“依赖已安装”。大屏仍需实际接入组件并完成构建验证，不能仅修改输出中的工程类型。

全部成功时，最终回复按以下结构输出（替换类型、名称和绝对路径；外层围栏仅用于展示格式）：

````markdown
<大屏 / PC>工程已创建。

工程位置：[<工程文件夹绝对路径>](<工程文件夹绝对路径>)

- 模板：CDTRSFE/vite-tpl
- Git 已初始化，pnpm 依赖已安装

启动命令：

```shell
cd "<工程文件夹绝对路径>"
pnpm dev
```
````

“工程位置”独占一段，必须输出 Markdown 链接，显示文字和链接目标都使用真实的工程文件夹绝对路径。例如实际工程位于 `/Users/puyuchun/Downloads/my-project` 时，该段完整源码为：

```markdown
工程位置：[/Users/puyuchun/Downloads/my-project](/Users/puyuchun/Downloads/my-project)
```

实际回复不带上述代码围栏。路径含空格时用尖括号包住链接目标。不要把位置只写成行内代码或纯文本，也不要把整份最终回复放进代码块，否则文件夹链接无法点击。

发送前检查“工程位置”段是否包含完整的 `[显示路径](绝对路径)`，且未被反引号包围；`cd` 命令里的路径不能代替该链接。若草稿是“位置：`/绝对路径`”，必须先改为链接再发送。文件格式校验不能替代这项最终回复检查。

成功回复到启动命令结束。省略 `ScaleLayout` 接入、画布尺寸、缩放方式等实现细节，省略构建/lint/类型检查/测试通过汇总及不影响创建和运行的警告，不追加“是否继续用浏览器验证”等追问。实际失败、未完成事项或影响使用的问题应简要说明，并据实调整成功措辞；用户主动询问验证细节时再提供。启动命令使用模板实际脚本，包管理器按实际使用结果填写。

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 用户只说“创建新工程”就开始后续流程 | 先展示类型选项（1. 大屏；2. PC），等待数字或类型名称回复后再继续 |
| 未指定工程名时根据业务自行命名 | 默认使用 `my-project` |
| 创建命令写成 npm create vite | 使用 `npx degit CDTRSFE/vite-tpl <project-dir>` |
| 选择大屏后仍保留未启用缩放的默认入口 | 在 `App.vue` 根部挂载内置 `ScaleLayout` 并验证构建 |
| 创建后只提示用户执行 `pnpm i` | 自动安装依赖并核实结果 |
| 安装失败仍报告工程就绪 | 分别报告生成状态与依赖安装状态 |
| 目标目录非空仍覆盖 | 停止并询问用户 |
