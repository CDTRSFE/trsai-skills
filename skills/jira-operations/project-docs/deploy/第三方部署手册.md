## 一、工程是什么

一个纯 Python3 标准库实现的 Jira 命令行工具 + AI 技能包：

- **执行层**：`scripts/jira_cli.py`，全量子命令（涵盖查询 search/get/count-by/watch、自检 whoami/serverinfo、元数据 createmeta/transitions/fields、全生命周期写操作 create/update/comment/assign/link/worklog/attach/delete、通用接口通道 api 及生效 apply），输出恒为单个 JSON 对象，**零第三方依赖**。
- **技能层**：`.claude/skills/zq-jira-query/`（真身，含 `SKILL.md` 与 `references/` 速查文档），工程根 `SKILL.md` 与 `.agents/skills/zq-jira-query/SKILL.md` 是指向真身的软链——三者同一份文件，改任意一侧等价。
- **配置层**：工程根 `jira_config.json`，定义多个 Jira 源（地址、凭据、路由字段）。

支持同时接多个 Jira 源，一次操作只作用于一个源，选源规则由技能定义约束（点名 → 业务标签 → 项目 key → 会话粘性，判不出就问用户）。写操作统一走两阶段门禁：预览 → 用户明确确认 → 执行，工具不提供自动撤销。

## 二、环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | macOS / Linux / Windows 均可（`install.py` 为 Python 脚本，天然跨平台） |
| Python | Python 3，**只用标准库**，无需 pip 安装任何依赖 |
| 网络 | 能访问你要接的每个 Jira 服务（内网源需 VPN/内网可达） |
| AI 助手（可选） | Claude Code 或 Kimi CLI，用于自然语言唤起技能；不用 AI 助手时也可直接命令行调用 |

## 三、安装步骤

### 标准流程（一键）

```bash
unzip zq-jira-query-*.zip
cd zq-jira-query
python3 install.py          # 自动完成释放技能、路径替换、软链修复、生成配置、跑单测
# 编辑 jira_config.json，填入各 Jira 源的地址与凭据（见第四节）
python3 install.py --check-only   # 验证凭据与连通性
```

`install.py` 是自包含脚本（技能内容已内嵌），依次做五件事：

1. 把技能文件释放到 `.claude/skills/zq-jira-query/`；
2. 把技能文件里的 `__ZQ_JIRA_ROOT__` 占位符替换为实际工程根路径；
3. 修复/重建两条技能入口软链（工程根 `SKILL.md`、`.agents/skills/` 入口），Windows 无权限建软链时退为复制并告警；
4. `jira_config.json` 不存在时从 `jira_config.example.json` 生成（已存在则不覆盖）；
5. 自检：跑单元测试；凭据已填时逐源 `whoami` 验证连通性（凭据还是模板占位值则跳过并提示）。

脚本幂等，可反复执行。可选参数：`--user` 额外把技能装到用户级目录（`~/.claude/skills/` 与 `~/.agents/skills/`，任意目录下都能被 AI 助手加载）；`--root <路径>` 显式指定工程根。

### 兜底（install.py 失效时的手工步骤）

<details>
<summary>展开手工步骤</summary>

1. 替换绝对路径前缀：

   ```bash
   NEW_ROOT=$(pwd)
   grep -rl "__ZQ_JIRA_ROOT__" "${NEW_ROOT}/.claude/skills/zq-jira-query/" \
     | xargs sed -i '' "s#__ZQ_JIRA_ROOT__#${NEW_ROOT}#g"   # Linux 把 sed -i '' 改成 sed -i
   ```

   若技能文件里还是开发机旧路径而非占位符，把上面命令里的 `__ZQ_JIRA_ROOT__` 换成旧路径再跑一遍。

2. 确认软链完好：

   ```bash
   ln -sf .claude/skills/zq-jira-query/SKILL.md SKILL.md
   mkdir -p .agents/skills/zq-jira-query
   ln -sf ../../../.claude/skills/zq-jira-query/SKILL.md .agents/skills/zq-jira-query/SKILL.md
   ```

3. 创建配置：`cp jira_config.example.json jira_config.json`。

</details>

> 交付侧（你自己）打包用 `python3 pack.py`：生成自包含 `install.py` 与 zip（默认精简交付包，`--full` 出完整工程包），`.git/`、`state/`、`logs/`、缓存与**真实凭据 `jira_config.json`** 一律排除在外。

## 四、配置 `jira_config.json`

配置结构（两个源的示例）：

```json
{
  "default_source": "Jira2",
  "sources": [
    {
      "name": "Jira1",
      "base_url": "https://jira1.example.com",
      "username": "账号",
      "password": "口令",
      "insecure": true,
      "routing_business_tag": "非涉密",
      "routing_business_desc": "一句话描述该源的业务范围",
      "routing_project_keys": ["XJRB", "XMKFB"]
    },
    {
      "name": "Jira2",
      "base_url": "http://jira2.example.com:8082",
      "username": "账号",
      "password": "口令",
      "insecure": false,
      "routing_business_tag": "涉密",
      "routing_business_desc": "一句话描述该源的业务范围",
      "routing_project_keys": ["XMKFB"]
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `default_source` | 是 | 没人指定源时的退路，必须与某个 `sources[].name` **逐字符一致**（大小写敏感）。正常路径不依赖它——判不出源时应停下来问用户 |
| `sources[].name` | 是 | 源名，调用时 `--source` 逐字传这个值 |
| `base_url` / `username` / `password` | 是 | 源地址与凭据，缺一即 `CONFIG_ERROR` |
| `insecure` | 是 | 自签名证书的源设 `true` |
| `routing_business_tag` | 强烈建议 | 业务标签（受控单值，如 `涉密` / `非涉密`），供 AI 判定第 2 级匹配与回显 |
| `routing_business_desc` | 建议 | 人读的描述，不参与匹配 |
| `routing_project_keys` | 强烈建议 | 该源下常用项目 key（大写数组），供 AI 判定第 3 级匹配 |

三个 `routing_` 字段**没有任何校验**——Python 侧不读，键名写错不会报错、只会让 AI 的选源判定静默失灵，填完肉眼核对一遍拼写。

可选调优参数（写在 source 对象内，均有默认值）：`timeout_seconds`(30)、`max_results_per_page`(50)、`hard_result_limit`(500)、`aggregate_scan_limit`(5000)、`total_deadline_seconds`(120)。

**不要**在配置里出现 `list_url` / `detail_url_template` / `browse_url_template`——那是遗留脚本的旧配置契约。

## 五、让 AI 助手加载技能

### Claude Code

技能真身就在 `.claude/skills/zq-jira-query/`，Claude Code 的项目级技能扫描目录正是这里，**无需额外动作**。在工程根启动新会话即可。

### Kimi CLI

Kimi CLI **不扫描 `.claude/skills/`**，它的项目级扫描目录是 `.agents/skills/` 和 `.kimi-code/skills/`。仓库已建好 `.agents/skills/zq-jira-query/SKILL.md` 软链入口，**无需额外动作**。

注意两点：

- **必须在工程根启动** `kimi`（项目根 = 向上最近的 `.git` 所在目录），否则项目级技能不会被扫描到。
- 技能列表在**会话启动时**加载。装好入口后要**新开一个会话**才生效。

也可手动唤起：`/skill:zq-jira-query`。

## 六、验证安装

`install.py` 的最后两步就是自动验证（单测 + 逐源 `whoami`），凭据填好后跑一次 `python3 install.py --check-only` 即可。需要手工逐项核对时按下面顺序执行：

```bash
# 1. 单元测试（unittest，无外部依赖；需要真实 Jira 的用例会默认跳过）
python3 -m unittest discover tests

# 2. 配置与连通性自检（对每个源各跑一次，源名逐字取自配置）
python3 scripts/jira_cli.py --source Jira1 whoami
python3 scripts/jira_cli.py --source Jira1 serverinfo
```

- 单测全绿（含 skip）→ 代码层 OK。
- `whoami` 返回 `ok: true` 与登录账号 → 配置、凭据、网络全链路 OK。
- 任一源不通：先 `curl -sS -o /dev/null -w "%{http_code}" <base_url>/rest/api/2/serverInfo` 自检网络，再核对凭据。

## 七、使用示例

### 1. 自然语言（推荐，经 AI 助手）

在工程根的新会话里直接说：

- 「我有哪些 Jira」「当前有哪些待处理 Jira」
- 「看看 XMKFB 项目有哪些逾期任务」
- 「统计一下 TRS 项目各状态的任务数」
- 「TRS-123 这个单的详情」
- 「帮我建一个 Jira」（走两阶段门禁：预览 → 你确认 → 执行）
- 「把 TRS-123 改成明天到期」「把这几条推到完成」
- 多源场合：「用涉密那个源查」「两边都查一下」

### 2. 直接命令行

通用形态：`python3 <工程根>/scripts/jira_cli.py --source <源名> <子命令> [参数]`

```bash
# 动态 JQL 搜索（列表查询建议追加 --fields issuetype,parent）
python3 scripts/jira_cli.py --source Jira1 search \
  --jql "project = TRS AND status != Done" --limit 20 --fields issuetype,parent

# 单条详情
python3 scripts/jira_cli.py --source Jira1 get TRS-123

# 分组计数（status / priority / project / fixVersion / assignee）
python3 scripts/jira_cli.py --source Jira1 count-by --jql "project = TRS" --group-by status

# 增量监控：只返回上次之后新增的 issue（首跑返回的是全量基线，不是新增）
python3 scripts/jira_cli.py --source Jira1 watch --jql "project = TRS AND created >= -7d" --name 近七天新建

# 建单两阶段：先 preview 拿到 plan_id，人确认后再 apply
python3 scripts/jira_cli.py --source Jira1 create --project TRS --type 任务 \
  --summary "标题" --description "描述" --preview
python3 scripts/jira_cli.py apply --plan-id <preview 返回的 plan_id>
```

纪律要点：

- **`--source` / `--config` 必须写在子命令之前**，写后面直接报参数错误。
- `search` 一律显式传 `--limit`（默认 20，最高 50），裸跑会把最多 500 条灌进输出。
- JQL 里内置状态名用英文（`Done` / `Open` / `In Progress`），团队自建中文状态才写中文。拿不准先 `count-by --group-by status` 看实际在用的状态名。
- plan 一次性消费且有有效期（create 与单条 update 5 分钟，批量 update 15 分钟）。
- 输出带 `truncated: true` 或 `partial: true` 时，结果不完整，不能当全量数据下结论。
- 标签与修复版本是**整体覆盖**语义，「加一个标签」要先读旧值拼成完整清单再传。

## 八、排障速查

| 现象 | 处置 |
|---|---|
| 命令 file not found | 仓库迁移后没跑 `install.py`（路径还是旧的），在工程根执行 `python3 install.py` 即可 |
| `CONFIG_ERROR` | 检查 `jira_config.json` 是否存在、JSON 是否合法、`default_source` 与 `sources[].name` 是否逐字符一致；`--source` 传的源名也须逐字一致（大小写敏感、不去空格） |
| `NETWORK_ERROR` / HTTP 000 | 内网/VPN 未连；`curl <base_url>/rest/api/2/serverInfo` 自检 |
| `CAPTCHA_LOCKED` | 账号被验证码锁定，必须浏览器登录 Jira 人工解除，期间不要重试 |
| `JQL_INVALID` 提示「没有该值」 | 多半是 JQL 状态名该写英文却写了中文，见第七节 |
| AI 发问后没调用技能 | 确认是在工程根启动的**新会话**；Kimi CLI 可 `/skill:zq-jira-query` 手动唤起 |
| `WATCH_JQL_CHANGED` | 同名监控换了 JQL，加 `--reset` 重置基线 |

运行产物：`state/plans/`（plan 暂存）、`state/audit.log`（全部写操作审计，含被拒的 apply）、`state/watch/`（监控基线）。`state/` 已被 git 忽略。

## 九、共享/交付前安全检查清单

把工程交给第三方之前，逐项过一遍：

1. **凭据已入库**。`jira_config.json` 不在 `.gitignore` 中（有意决策），如果你克隆的是开发方的仓库，里面带的是**开发方的真实账号口令**。交付前必须：替换为接收方自己的凭据，或在交付物中删除该文件、只留 `jira_config.example.json` 模板。
2. **历史提交里也有凭据**。仅改当前文件不够，git 历史里仍可翻出旧凭据。对外共享建议：用干净目录重新初始化仓库，或先做历史清洗。
3. **用 `pack.py` 打的包天然干净**：技能内路径是占位符（安装时注入）、软链由 `install.py` 重建、真实凭据物理排除。直接交付 zip 即可；若绕过 `pack.py` 手工打包，需自己保证这三点。
4. 接收方解压后**只需跑 `install.py` + 填配置**，无需任何其他手工步骤。
5. **`scripts/jira_query.sh` 与 `scripts/jira_notify_check.sh` 是遗留旧脚本**，走已废弃的旧配置格式，任何情况下不得调用，也不要写进新文档。
6. 提醒接收方：写操作无撤销、无删除/关闭接口；两阶段门禁是安全设计，不要绕过。
