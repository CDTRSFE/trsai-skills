# 配置文件说明

工程根 `jira_config.json` 的结构、字段含义，以及本技能的目录约定。

**这个文件助手只读不写。** 需要改配置时，把要改的内容告诉用户，由用户自己动手。

## 目录

- 一、配置文件路径
- 二、结构（字段形态示例）
- 三、基础字段
- 四、三个 `routing_` 判定字段
- 五、运行产物目录
- 六、仓库迁移后必做的路径替换

---

## 一、配置文件路径

```text
<本技能目录>/jira_config.json
```
（本地绝对路径示例：`/Users/zhaoqing/trs/trsai-skills/skills/jira-operations/jira_config.json`）

日常调用一律不传 `--config`——脚本默认自动读取同目录下的 `jira_config.json`。只有需要临时指向另一份配置（例如自检）时才显式传，且必须写在子命令之前。

模板在同目录的 `jira_config.example.json`。

## 二、结构（字段形态示例）

本示例只说明字段形态与嵌套位置，**取值以工程根 `jira_config.json` 实际内容为准**，不承诺与实际一致。

```json
{
  "default_source": "Jira2",
  "sources": [
    {
      "name": "Jira1",
      "base_url": "https://jira1.example.com",
      "username": "账号占位",
      "password": "口令占位",
      "insecure": true,
      "timeout_seconds": 30,
      "routing_business_tag": "非涉密",
      "routing_business_desc": "一句话描述该源的业务范围",
      "routing_project_keys": ["XJRB", "XMKFB"]
    },
    {
      "name": "Jira2",
      "base_url": "http://jira2.example.com",
      "username": "账号占位",
      "password": "口令占位",
      "insecure": false,
      "routing_business_tag": "涉密",
      "routing_business_desc": "一句话描述该源的业务范围",
      "routing_project_keys": ["XMKFB"]
    }
  ]
}
```

## 三、基础字段

**`default_source`：没人指定源时才会用到的退路，当前是 `Jira2`。它不代表「本次的正确源」。**

正常路径永远不依赖它：判不出源就停下来问用户，不落默认。

**这里没有安全网**（2026-08-11 用户拍板，见 `project-docs/decisions/2026-08-10-多jira实例选择判定.md` 的 D5）：漏写 `--source` 时请求会静默落到 `Jira2`，不报任何错。而两个源都有 `XMKFB`，落错源会返回另一个库里同号的单、形态完全正常。所以「每次调用都显式写 `--source`」这条纪律**只能靠你自己守**，没有任何东西会拦住。

该值必须与某个 `sources[].name` **逐字符一致**（大小写敏感、无前后空格）。比较是精确匹配，既不归一化大小写也不去空格，对不上直接报 `CONFIG_ERROR`。

**`base_url` / `username` / `password`**：源地址与凭据。三者缺一即 `CONFIG_ERROR`。

**`insecure`**：自签名证书的源设为 `true`。

**五个调优参数**，均可省略，默认值如下，都写在 source 对象内（上面示例只保留了 `timeout_seconds` 一个，用来示范嵌套层级）：

| 参数 | 默认值 |
|---|---|
| `timeout_seconds` | 30 |
| `max_results_per_page` | 50 |
| `hard_result_limit` | 500 |
| `aggregate_scan_limit` | 5000 |
| `total_deadline_seconds` | 120 |

**三个老字段**（`list_url`、`detail_url_template`、`browse_url_template`）属于遗留脚本的旧配置契约，本技能的 `jira_config.json` 中**不得出现**。

## 四、三个 `routing_` 判定字段

这三个字段是源判定的数据来源。**Python 侧完全不读它们**——配置加载只搬运它认识的那几个键，其余键静默忽略且不报错。所以这三个字段纯粹给模型看。

代价是**它们没有任何校验**：键名写错不会报错，只会让判定静默失灵。三个一组同前缀，肉眼扫一遍就能看出缺没缺。

| 字段名 | 类型 | 语义 | 判定中的作用 |
|---|---|---|---|
| `routing_business_tag` | 字符串，受控单值 | 词表**只有** `涉密` / `非涉密` 两个值，每个源恰好一个（此处「涉密」是内部俗称，不代表法定密级） | 第 2 级唯一匹配依据；同时是回显括号里的内容 |
| `routing_business_desc` | 字符串，一句话 | 人读的自由描述 | **不参与任何匹配**，只用于让维护者看懂这个源是干什么的 |
| `routing_project_keys` | 字符串数组 | 该源下常用的 Jira 项目 key，元素统一大写 | 第 3 级匹配依据 |

判定规则本身见 `SKILL.md` 的《选哪个 Jira 源（每次操作前必做）》，本文不重复。

清单由用户自行维护，助手不代填、不代改。未登记的项目会走「零命中 → 继续下一级」，**不要提示用户「该补登了」**。

## 五、运行产物目录

| 路径 | 内容 |
|---|---|
| `state/plans/` | 两阶段写操作的 plan 暂存。一次性消费、有效期分档：`create` 与单条 `update` 5 分钟，批量 `update`（去重后两条及以上）15 分钟。以返回体的 `ttl_seconds` / `expires_at` 为准 |
| `state/audit.log` | 所有写操作审计（含被拒绝的 `apply`），单行 JSON。`update` 逐条即时写入而非批末统一写，含改前改后值、走过的每一跳状态、是否半成品——批量执行被中途打断时，靠它还原做到了哪一条 |
| `state/watch/` | 增量监控状态，按监控名的哈希存文件 |

`state/` 已被 git 忽略，不入库。

## 六、路径解析与定位说明

`scripts/jira_cli.py` 在执行时会自动通过自身脚本文件路径定位所在技能根目录（`SKILL_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`），并默认查找同级目录下的 `jira_config.json`，因此无论本技能放在项目本地（例如 `/Users/zhaoqing/trs/trsai-skills/skills/jira-operations/`）还是全局目录（例如 `~/.agents/skills/jira-operations/`），脚本均可自适应寻址，无需手动替换路径。

若需要临时使用其他自定义路径的配置文件，可使用 `--config` 参数：

```bash
python3 <本技能目录>/scripts/jira_cli.py --config /path/to/custom_jira_config.json --source Jira1 whoami
```
