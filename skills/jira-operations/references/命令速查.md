`jira_cli.py` 十二个子命令的完整调用形态与查询纪律。写操作（`create` / `update` / `apply`）的规则不在本文，见 `更新操作规则.md`。

## 一、通用形态

```bash
python3 <本技能目录>/scripts/jira_cli.py --source <源名> <子命令> [参数]
```

下面所有示例里的 `<本技能目录>` 都指本技能所在目录的绝对路径，实际执行时要写全，本地路径例如：

```text
/Users/zhaoqing/trs/trsai-skills/skills/jira-operations
```

- `--source` 与 `--config` 都是主解析器参数，**必须写在子命令之前**。写成 `jira_cli.py whoami --source Jira1` 会直接报参数错误。
- 源名怎么定见 `SKILL.md` 的《选哪个 Jira 源（每次操作前必做）》。下面示例里的 `<源名>` 是占位，实际要逐字填配置里的 `name`。
- 日常调用一律不传 `--config`，脚本默认就读技能目录下的 `jira_config.json`。

## 二、查询类命令

```bash
# 动态 JQL 搜索（JQL 由你按用户意图组装）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> search --jql "project = TRS AND status != Done" --limit 20

# 单条详情（key 自动转大写）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> get TRS-123

# 分组计数（status / priority / project / fixVersion / assignee）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> count-by --jql "project = TRS" --group-by status

# 增量监控：只返回上次之后新增的 issue
python3 <本技能目录>/scripts/jira_cli.py --source <源名> watch --jql "project = TRS AND created >= -7d" --name 近七天新建
```

`watch` 另有两个开关：`--peek` 只看不标记（不改变状态）、`--reset` 换 JQL 时重置基线。同名换 JQL 而不加 `--reset` 会报 `WATCH_JQL_CHANGED`。

## 三、辅助类命令

```bash
# 列字段（含 customfield id），--grep 过滤，--full 看完整定义
python3 <本技能目录>/scripts/jira_cli.py --source <源名> fields --grep 关键词

# 查某单当前可用的状态流转及每条流转的必填字段
python3 <本技能目录>/scripts/jira_cli.py --source <源名> transitions TRS-123

# 查某项目某类型建单的必填字段
python3 <本技能目录>/scripts/jira_cli.py --source <源名> createmeta --project TRS --type 任务

# 连通性与身份自检
python3 <本技能目录>/scripts/jira_cli.py --source <源名> whoami
python3 <本技能目录>/scripts/jira_cli.py --source <源名> serverinfo
```

## 四、查询纪律（四条，都是实测踩出来的）

**1. `search` 一律显式传 `--limit`。**

缺省用 20，用户明确要更多时最高 50。不带 limit 裸跑会走 `hard_result_limit=500`——最多十轮往返，并把五百条 issue 的 JSON 全量灌进上下文。

**2. JQL 里的内置状态名要用英文。**

这套 Jira 装了中文语言包，界面和 `get` 输出里状态显示为中文（待办／完成），但手写 JQL 时内置状态必须写英文原始名（`Done`、`Open`、`In Progress`）或状态 id。写 `status = 完成` 会报 `JQL_INVALID: "status"域中没有"完成"值`。

团队自建的中文状态（测试、联调中、待合并等）反而按中文名写。

拿不准某个状态名该怎么写时，先跑一次 `count-by --group-by status` 把该项目实际在用的状态名列出来——它内部按状态 id 计数，不受本条影响。不要猜，不要编。

**3. issue key 不要猜。**

优先按 `[A-Z][A-Z0-9]+-[0-9]+` 模式识别。用户要看详情却没给 key 时，让用户补 key。

**4. 截断标记必须转述给用户。**

- `search` 的 `truncated: true` 表示结果不完整，原因看 `truncated_reason`：`limit` 是你自己给的上限，`hard_result_limit` 是总量硬上限 500，`total_deadline_seconds` 是总耗时超时。
- `count-by` 扫描分支的 `partial: true` 是另一个字段，含义同样是不完整。

两个字段都必须向用户声明「结果不完整」，不得当作全量数据下结论。

搜索结果默认只含 summary / status / assignee / duedate / priority / fixVersions 六个字段，要更多字段用 `--fields a,b` 追加。**列表类回答的固定表格需要「是否子任务」与「关联父任务」两列，列表查询一律追加 `--fields issuetype,parent`**：是否子任务看 `issuetype.subtask`，关联父任务取 `parent.key`（无父单则该字段为 null）。

## 五、`count-by` 的两条路径

两条路径行为不同，别混。

**枚举维度**（`status` / `priority` / `project` / `fixVersion`）：逐个候选值发计数查询，请求数等于候选值个数。没有内部截止，永远不会返回 `partial`。

但 `/rest/api/2/status` 返回的是**全局所有状态**，几十个状态就是几十次请求。所以必须先用 `project` 或时间范围把 JQL 收窄。

调用时把命令超时设到 **180 秒以上**。脚本内部 `total_deadline_seconds` 默认 120 秒，与命令行默认的 120 秒几乎重合，不调会出现「有时出结果、有时被杀」的抖动型故障。

**非枚举维度**（如 `assignee`）：走翻页扫描，受 `aggregate_scan_limit`（默认 5000 条）与 `total_deadline_seconds`（默认 120 秒）双重约束，**可能返回 `partial: true`**。此时必须向用户声明「至少 N 条、结果不完整」，不得当作确定数字报出。

## 六、`watch` 的首跑语义

这条极易误报，务必遵守。

对某个监控名**第一次**运行时，返回的 `new_count` 是**全量基线，不是新增**。必须如实说明「这是首次建立基线，共 N 条」。

**绝不能报成「新增 N 条」**——那是会直接误导决策的错报。

怎么判断是不是首跑：执行前看工程根 `state/watch/` 下有没有该监控名对应的哈希文件，没有就是首跑。

监控名要固定：同一用途永远用同一个名字。换名字等于新建监控，会再来一次全量基线。

## 七、写操作命令（两阶段门禁：先 --preview 后 apply）

```bash
# 1. 创建主单 / 子任务
# 创建主任务
python3 <本技能目录>/scripts/jira_cli.py --source <源名> create \
  --project TRS --type 任务 --summary "标题" --preview
# 创建子任务（传入 --parent 自动识别所属项目及子任务类型）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> create \
  --parent XMKFB-12099 --summary "子任务标题" --preview

# 2. 评论管理（comment）
# 查看已有评论
python3 <本技能目录>/scripts/jira_cli.py --source <源名> comment --key TRS-123 --list
# 添加评论（支持 Markdown，自动转 wiki）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> comment --key TRS-123 --body "进度更新" --preview

# 3. 经办人分配（assign）
# 分配给指定人 / 分配给我 / 清空未分配
python3 <本技能目录>/scripts/jira_cli.py --source <源名> assign --key TRS-123 --to zhangsan --preview
python3 <本技能目录>/scripts/jira_cli.py --source <源名> assign --key TRS-123 --to-me --preview
python3 <本技能目录>/scripts/jira_cli.py --source <源名> assign --key TRS-123 --unassign --preview

# 4. 单据关联（link）
# 查询系统支持的关联类型
python3 <本技能目录>/scripts/jira_cli.py --source <源名> link --list-types
# 建立关联（如 Relates / Blocks / Clones）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> link --inward TRS-1 --outward TRS-2 --type Relates --preview

# 5. 工时登记（worklog）
# 查看已有工时
python3 <本技能目录>/scripts/jira_cli.py --source <源名> worklog --key TRS-123 --list
# 登记工时（支持 2h 30m, 1d 等）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> worklog --key TRS-123 --time "2h 30m" --comment "完成接口联调" --preview

# 6. 附件管理（attach）
# 查看已有附件
python3 <本技能目录>/scripts/jira_cli.py --source <源名> attach --key TRS-123 --list
# 上传附件
python3 <本技能目录>/scripts/jira_cli.py --source <源名> attach --key TRS-123 --file /path/to/doc.pdf --preview

# 7. 删除单据（delete，高危操作需确认）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> delete --key TRS-999 --preview

# 8. 修改字段与流转（update）
python3 <本技能目录>/scripts/jira_cli.py --source <源名> update --key TRS-123 --set duedate=明天 --status 完成 --preview

# 9. 通用 REST 接口逃生通道（api：覆盖全量内置与插件 API）
# 读操作（GET/HEAD）：自动鉴权并直接输出结果
python3 <本技能目录>/scripts/jira_cli.py --source <源名> api \
  --path /rest/api/2/issue/TRS-123/watchers

# 写操作（POST/PUT/DELETE/PATCH）：必须带 --preview，生成两阶段确认 plan
python3 <本技能目录>/scripts/jira_cli.py --source <源名> api \
  --method POST \
  --path /rest/api/2/issue/TRS-123/watchers \
  --data '"zhangsan"' \
  --preview

# 10. 执行生效（apply，统一凭 preview 返回的 plan_id 执行）
python3 <本技能目录>/scripts/jira_cli.py apply --plan-id plan_xxxxxxxx
```

## 八、未在常用命令列表中的操作处理机制（SOP）

当用户提出的 Jira 需求未被上述专用子命令直接覆盖（例如：看板/Sprint 操作、关注者管理、投票、版本/组件发布、过滤器管理、插件接口等）时，按以下 SOP 标准流程处理：

1. **零依赖直接兜底**：使用 `jira_cli.py api` 通用接口通道，无需编写新脚本或调用外部浏览器，底层自动复用会话鉴权、源路由、超时控制与异常审计。
2. **读操作直接执行**：
   - 请求方法为 `GET` 或 `HEAD` 时，直接运行 `api --method GET --path <PATH>` 获取结构化 JSON 并解析呈现给用户。
3. **写操作两阶段安全门禁**：
   - 任何 `POST` / `PUT` / `DELETE` / `PATCH` 等变更数据的操作，**必须带 `--preview`** 生成预览 plan。
   - 向用户清晰展示：目标源、请求方法、接口路径以及请求体载荷（Payload），等待用户明确确认。
   - 获得用户明确确认后，执行 `apply --plan-id <plan_id>` 完成落库。
4. **常用扩展接口速查**：
   - **关注者（Watchers）**：
     - 查询：`GET /rest/api/2/issue/<KEY>/watchers`
     - 添加：`POST /rest/api/2/issue/<KEY>/watchers`，Body: `"username"`
     - 移除：`DELETE /rest/api/2/issue/<KEY>/watchers?username=xxx`
   - **投票（Votes）**：
     - 投票：`POST /rest/api/2/issue/<KEY>/votes`
     - 撤销投票：`DELETE /rest/api/2/issue/<KEY>/votes`
   - **敏捷看板与 Sprint（Agile API）**：
     - 查询看板：`GET /rest/agile/1.0/board`
     - 查 Sprint：`GET /rest/agile/1.0/board/<boardId>/sprint`
     - 查 Sprint 下任务：`GET /rest/agile/1.0/sprint/<sprintId>/issue`
   - **版本与模块（Version / Component）**：
     - 查项目版本：`GET /rest/api/2/project/<KEY>/versions`
     - 创建版本：`POST /rest/api/2/version`，Body: `{"name":"1.0.0","project":"TRS"}`
     - 查项目模块：`GET /rest/api/2/project/<KEY>/components`
