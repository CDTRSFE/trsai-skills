# TRS AI 前端开发规范草稿

> 说明：本文先作为问题池 / 经验池集中记录，后续确认稳定后，再按领域拆分到对应 Skill 或代码审查清单中。

## 1. 无数据展示

- 页面不能直接空着。
- 接口无数据、列表为空、图表无数据、统计模块无数据时，需要展示类似 `no-data` 的空状态组件。
- 如果项目里没有现成的 `no-data` / 空状态组件，AI 不应自行随意实现，需要先提示用户确认组件方案、位置和样式。

## 2. 接口文档和实际返回不一致

- 只要接口文档和实际返回不一致，并且可能影响业务展示、计算、判断或提交，AI 必须提示用户确认，不能擅自兜底处理。
- 典型场景包括：
  - 字段名不一致，例如 `totalNum` 和 `total`。
  - 字段类型不一致，例如文档是 `number`，实际返回 `string`。
  - 数据层级不一致，例如文档是 `data.list`，实际是 `data.records`。
  - 后端漏字段。
  - 前端页面需要字段，但接口没有返回。
  - 返回值会影响业务判断、图表统计、表格数据、分页、筛选条件等。
- 核心原则：影响业务的数据问题，AI 不能自己猜。

## 3. 表格高度和内部滚动

- 表格高度根据默认分页条数设置。
- 例如默认分页是 `10` 条，则表格高度应刚好容纳 `10` 行数据。
- 数据少于默认分页条数时，表格仍保持对应高度，避免页面显得空。
- 数据多于当前表格高度时，表格内部滚动。
- 不允许表格无限撑开页面。
- 分页区域不应被表格内容挤走。

## 4. 图表间距

- 图表上下左右都需要有适当间距，不能贴边。
- 图表统一优先使用 `echarts`。
- 使用 `echarts` 时需要检查 `grid`、`legend`、`title`、`axisLabel` 是否贴边或遮挡。
- 必要时设置 `grid.left`、`grid.right`、`grid.top`、`grid.bottom` 和 `containLabel: true`。

## 5. 页面文字和设计稿保持一致

- 用户输入、设计稿、截图或链接中已经给出的模块标题、字段文案、tab 文案、按钮文案、数字文案，AI 实现时必须严格保持一致。
- 中文不能擅自换同义词。
- 数字不能擅自改。
- 标题不能简写。
- 模块名不能重新组织。
- tab、按钮、表格列名、卡片标题都要一致。
- 核心原则：设计稿或用户输入给了什么，页面就实现什么。

## 6. 数字格式化

- 数字格式化优先复用项目已有公共函数。
- 具体公共函数和使用方式后续由用户提供。
- 不应在页面里临时写 `toFixed`、手动除以 `10000`、手动拼接单位等重复逻辑。

## 7. 公共方法复用和新增

- 如果项目已有公共方法，必须优先复用。
- 公共方法目录：`src/utils`。
- 如果确实没有现成公共方法，需要新增到 `src/utils`，并且必须写清楚注释。
- 适用范围包括：
  - 时间格式化。
  - 数字格式化。
  - 金额格式化。
  - 百分比格式化。
  - 空值处理。
  - 单位转换。
  - 大数字转万、亿等。

## 8. Tab 请求懒加载

- tab 场景默认懒加载，只请求当前激活 tab。
- 已请求数据可按业务决定是否缓存。
- 不能默认一次性请求所有 tab。
- 不要为了省事在页面初始化时把所有 tab 的接口全部请求完。

## 9. Loading 粒度

- 哪个模块请求数据，就在哪个模块展示 loading。
- 不要因为局部模块加载导致整个页面不可操作。
- 表格、图表、统计卡片等模块应优先使用各自区域内的 loading。

## 10. 不滥用 Promise.all

- 不要无脑使用 `Promise.all`。
- 只有多个请求相互独立，且页面确实必须等它们全部完成后才能统一渲染时，才考虑使用 `Promise.all`。
- 否则应拆分请求、独立 loading、独立失败处理。

## 11. Mock 数据和硬编码清理

- 开始静态开发可以使用 mock 数据。
- 接口对接完成后，应清理 mock 数据和硬编码。
- 检查项包括：
  - mock 数组。
  - 写死统计值。
  - 写死图表数据。
  - 临时 `setTimeout`。
  - 临时接口 fallback。
  - 调试 `console.log`。

## 12. 非前端问题处理

- 当问题来源可能是后端、接口、需求、数据权限、环境配置时，AI 必须先定位并说明依据。
- AI 应提出 1-2 个解决方案，让用户确认后再处理。
- 不得擅自通过前端兜底掩盖问题。

## 13. 组件和文件结构

- AI 写代码前必须先查看项目已有公共组件、公共方法、资源目录和同类页面实现。
- 不允许直接新建重复逻辑。
- 页面局部组件、公共组件、工具函数等应遵循项目已有结构。
- 组件目录、文件夹、`components` 放置规则后续结合具体项目继续补充。

## 14. SVG 图标资源

- svg 图标统一放在 `src/assets/icons` 目录下。
- 文件名使用英文。
- 使用方式按 `icons-文件名` 调用。
- 示例：

```text
src/assets/icons/search.svg
```

```vue
<icons-search />
```

## 15. 图片资源

- 图片统一放在 `src/assets/images` 目录下。
- 图片文件统一使用英文命名。
- `images` 目录下默认不再按业务、页面或模块继续创建子文件夹。
- 普通图片资源尽量在 `images` 下打平存放，避免出现 `screen-previews`、`screen-switch-tabs`、`temple-police`、`temple-warning` 这类多层分类目录。
- 截图资源如果也放到 `images` 下，不建议再单独按截图类型建文件夹；需要区分用途时优先通过英文文件名表达。
- 适用资源包括：`png`、`jpg`、`jpeg`、`webp`、`gif` 等普通图片资源。

## 16. Git 提交和推送

- 生成 commit 信息时必须遵循团队提交规范。
- commit 后不能默认 push。
- 是否推送远程必须询问用户确认。
